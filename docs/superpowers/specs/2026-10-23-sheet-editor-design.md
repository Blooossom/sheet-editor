# Sheet Editor 설계

작성일: 2026-10-23

## 1. 의도와 배경

- 사용자는 Office 365 라이선스가 만료된 뒤 구글 스프레드시트로 엑셀 파일을 다뤄 왔다. 그런데 매번 브라우저를 열고, 파일을 업로드하고, 편집한 뒤 다시 받는 과정이 번거롭다.
- 원하는 것: **파일을 더블클릭하면 바로 열리고, 표를 보면서 셀 값 몇 개를 고친 뒤 저장하면 원본 파일에 바로 반영되는** 가벼운 맥 데스크톱 앱.
- 기존 무료 프로그램(LibreOffice, Numbers)은 고려하지 않는다. 직접 만드는 이유는 **쓰면서 불편하거나 더 필요한 기능을 자유롭게 덧붙일 수 있는 나만의 도구**를 갖기 위해서다.
- 이후 기능 추가는 주로 Claude에게 맡긴다. 따라서 코드는 기능을 덧붙이기 쉬운 구조여야 한다.

## 2. 실제 사용 방식

- 주된 작업: 표를 보고 **값 몇 개를 수정**하는 정도다.
- 파일 형식은 **.xlsx**와 **.csv** 두 가지다.
  - csv는 대부분 **DB에서 내보낸 파일**이다. 행이 수천~수만 개일 수 있다.
  - xlsx에는 **수식이 별로 없다** (사용자 답변). 행 수는 확인되지 않았으므로 xlsx도 csv와 같은 규모(수만 행)를 견디는 것을 기준으로 한다 (Claude 판단).
- 파일은 혼자 보는 것일 수도 있고, 다른 사람에게 받아서 고친 뒤 다시 보낼 것일 수도 있다. 어느 쪽인지 정할 수 없으므로, **다시 보내도 문제없는 상태로 저장하는 것**을 기준으로 삼는다.

## 3. 목표 / 비목표 / 반목표

### 목표 (첫 버전)
1. xlsx와 csv를 연다. 방법은 더블클릭(기본 앱 지정), 드래그 앤 드롭, ⌘O 세 가지다.
2. 표를 보면서 셀 값을 고친다.
3. ⌘S를 누르면 **원본 파일을 바로 덮어쓴다**. 사용자가 확정한 방식이다.
4. 행이 많은 파일에서도 고칠 행을 빨리 찾도록 검색과 필터를 제공한다.

### 비목표 (첫 버전에서는 하지 않음, 필요해지면 나중에 추가)
- 행·열 추가나 삭제
- 서식(색상, 글꼴, 테두리 등) 편집
- 새 파일 만들기, 다른 이름으로 저장, 형식 변환
- 차트, 피벗, 조건부 서식 편집 등 엑셀 고급 기능
- .xls(구형), .ods 등 다른 형식

### 반목표 (기능이 동작하더라도 이렇게 되면 실패)
- **저장한 뒤 원본의 서식, 병합 셀, 수식, 다른 시트, 열 너비 등 고치지 않은 부분이 바뀌거나 사라지는 것.** 가장 치명적인 실패다.
- csv를 저장했더니 인코딩(한글 깨짐), 구분자, 줄바꿈 방식, 따옴표 처리가 원본과 달라지는 것
- 큰 파일을 열거나 스크롤할 때 버벅이는 것
- 실행이 느리고 무거운 것. "브라우저 여는 게 귀찮다"를 해결하려는 프로그램이 그보다 무거우면 의미가 없다.

## 4. 사용자가 정한 것

- **화면 레이아웃은 시안 C "탐색형"**으로 정했다. 구성은 아래와 같다.
  - **상단 바**: 파일 이름, 행 개수, 수정 여부 표시(● 수정됨), 저장 버튼(⌘S)
  - **입력줄**: 선택한 셀의 주소(예: `C3`)와 내용을 보여 주고, 여기서 직접 편집할 수 있다. 수식 셀이면 수식을 보여 준다.
  - **가운데 표**: 행·열 머리글이 있는 격자다. 셀을 더블클릭하거나 바로 타이핑해서 편집한다. 수정한 셀은 노란색 배경으로 표시한다(저장하면 표시를 지운다).
  - **오른쪽 패널**: 값 검색과 열별 필터(체크박스로 값 선택)
  - **하단 시트 탭**: xlsx만 해당하며, 시트를 전환한다.
- **저장은 원본을 바로 덮어쓴다.**
- 지원 형식은 xlsx와 csv다.
- **다른 파일을 열면 새 창으로 연다.** 이미 열려 있는 파일을 다시 열면 그 창을 앞으로 가져온다 (Claude 판단). 따라서 상태(문서 데이터, 수정 내역, 되돌리기 기록, 저장 여부 확인)는 창마다 따로 관리한다.
- 형상관리는 처음부터 git으로 한다. 프로젝트 위치는 `sandbox/sheet-editor/`.

## 5. Claude가 정한 것 (사용자 확인 대상)

- **플랫폼과 기술**: Tauri + React + TypeScript로 만드는 맥 데스크톱 앱. Electron보다 가볍고 빨리 뜨며, 사용자가 React/TypeScript에 익숙해서 코드를 읽기 편하다.
- **xlsx 저장 방식, 핵심 설계**: 파일 전체를 라이브러리로 다시 쓰지 않는다. **xlsx(zip) 안의 XML에서 수정된 셀만 바꿔 넣고**, 나머지 파트는 바이트 그대로 둔다. 일반적인 스프레드시트 라이브러리로 읽고 다시 쓰면 서식이나 기타 요소가 손실될 수 있기 때문이다.
  - 문자열 값은 공유 문자열(sharedStrings) 대신 인라인 문자열(`t="inlineStr"`)로 기록해도 된다. 기존 sharedStrings는 건드리지 않는다.
  - 기존 셀의 스타일 속성(`s=`)은 유지한다.
- **수식 처리** (수식이 적다는 답변에 따라 단순하게 간다: 파일 전체를 읽어 수식 엔진에 올려도 된다)
  - 화면에서는 값을 고치면 그 값을 참조하는 수식 셀도 즉시 다시 계산해서 보여 준다(예: HyperFormula 같은 수식 엔진 사용).
  - 저장할 때는 엑셀이나 구글 시트로 열 때 다시 계산되도록 표시한다(`calcPr fullCalcOnLoad="1"`). 수식 셀에 저장된 캐시 값을 갱신할지는 구현자가 판단한다.
  - 수식 셀 자체를 편집할 수 있게 할지(입력줄에서 `=`로 시작하는 입력)는 첫 버전에서 지원하는 쪽을 기본으로 한다.
- **csv**: 인코딩을 자동 판별(UTF-8, UTF-8 BOM, EUC-KR/CP949)하고 구분자도 자동 판별한다. 저장할 때는 원래 인코딩, BOM 유무, 구분자, 줄바꿈(LF/CRLF)을 그대로 유지한다.
- **검색·필터**는 화면 표시만 바꾼다. 파일 내용이나 행 순서는 바꾸지 않는다.
- **되돌리기**: ⌘Z(되돌리기)와 ⌘⇧Z(다시 하기)를 지원한다.
- **큰 파일**: 표는 가상 스크롤(보이는 행만 그리기)로 수만 행에서도 부드럽게 동작해야 한다.
- **저장하지 않고 닫을 때**: 창마다 저장할지 묻는다. 앱을 종료할 때는 수정된 창마다 묻는다.
- **구조**: 나중에 기능을 덧붙이기 쉽도록 파일 형식 처리(xlsx/csv 읽기·쓰기), 표 화면, 검색·필터, 수식 계산을 각각 분리한다.

## 6. 구현자에게 맡기는 것

- 표 컴포넌트, 수식 엔진, zip·XML 처리 라이브러리 선택
- 키보드 이동(방향키, Tab, Enter) 등 세부 편집 동작
- 숫자와 날짜의 화면 표시 형식을 어디까지 원본 서식(numFmt)대로 보여 줄지
- 저장 실패(권한, 다른 프로그램이 파일을 잠근 경우 등) 처리 방식
- 테스트 전략. 다만 **"고치지 않은 부분은 저장 후에도 원본과 같다"는 것을 검증하는 테스트는 반드시 있어야 한다.**
