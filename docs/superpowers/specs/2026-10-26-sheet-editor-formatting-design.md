# Sheet Editor 2차 설계: 서식 표시와 서식 편집

작성일: 2026-10-26
선행 문서: `docs/superpowers/specs/2026-10-23-sheet-editor-design.md` (1차 설계, 이하 "1차")

## 1. 의도와 배경

- 1차 앱으로 실제 업무 양식(주간 업무 보고 xlsx)을 열어 보니, 값만 보이고 Excel에서 보던 모습이 사라졌다. 병합된 제목·날짜 칸이 쪼개지고, 여러 줄 업무 내용이 첫 줄만 보이며, 배경색·테두리·굵은 글씨·정렬·행 높이·열 너비·"9월 28일" 같은 날짜 형식이 모두 빠졌다.
- 사용자는 이런 **양식형 xlsx**를 열어 짧은 칸(날짜·특이사항)도 채우고, **여러 줄 칸의 줄을 추가·수정**하기도 한다.
- 목표: **Excel에서 보던 모습 그대로 보이고, 그 상태에서 값과 서식을 고칠 수 있게** 한다. 1차의 원칙("손대지 않은 부분은 그대로 보존")은 그대로 유지한다.

## 2. 목표 / 비목표 / 반목표

### 목표
1. **서식 표시** (xlsx)
   - 병합된 칸(가로·세로)
   - 열 너비, 행 높이, 숨긴 행·열
   - 배경색(단색 채우기), 테두리(선 종류·굵기·색)
   - 글꼴: 종류, 크기, 굵게, 기울임, 밑줄, 취소선, 색
   - 가로·세로 정렬, 줄 바꿈(칸 안 여러 줄), 들여쓰기
   - 숫자·날짜 표시 형식: Excel 형식 코드 전체를 기준으로 한다(예: `m"월" d"일"`, `#,##0`, 통화, 백분율, 지수, 구간 `;`, `[Red]` 색).
   - 틀 고정(시트에 저장된 고정 행·열)
2. **편집**
   - 짧은 칸은 지금처럼 바로 타이핑한다.
   - 여러 줄 칸은 Excel처럼 **⌥+Enter로 줄 바꿈, Enter로 확정**한다.
   - 편집기는 그 칸(병합이면 병합 영역) 크기로 열리고, 내용이 길면 늘어난다.
   - 병합된 칸은 하나의 칸으로 선택·이동·편집한다.
3. **서식 편집** (사용자 요청, Excel 홈 탭의 자주 쓰는 기능 기준)
   - 글꼴: 굵게(⌘B), 기울임(⌘I), 밑줄(⌘U), 크기, 색, 글꼴 종류
   - 배경색
   - 테두리: 모든 테두리, 바깥 테두리, 테두리 지우기, 선 굵기(가는·보통·굵은)
   - 가로·세로 정렬, 줄 바꿈 켜기·끄기
   - 병합하기, 병합 풀기
   - 숫자 표시 형식: 일반, 숫자(`#,##0`), 통화(`₩#,##0`), 백분율(`0%`), 날짜 몇 가지(`yyyy-mm-dd`, `m"월" d"일"`)
   - 열 너비·행 높이: 머리글 경계를 끌어서 조절
   - 서식 지우기
   - 모든 서식 변경은 ⌘Z / ⌘⇧Z로 되돌리기·다시 실행
4. **화면**: 입력줄 위에 Excel 홈 탭을 간단히 줄인 **도구 막대**를 하나 둔다. 1차 레이아웃(상단 바, 입력줄, 표, 오른쪽 검색·필터 패널, 시트 탭)은 유지한다.

### 비목표
- 조건부 서식 표시·편집, 셀 스타일 갤러리, 서식 복사(붓)
- 그림·차트·도형 표시
- 한 칸 안에서 일부 글자만 다른 글꼴인 경우(rich text)는 칸 전체 글꼴로 보이게 한다(파일 안의 rich text는 그 칸을 고치지 않는 한 보존).
- 무늬 채우기·그라데이션 채우기 편집(표시는 대표 색으로 근사해도 됨)
- 인쇄·페이지 설정
- csv의 서식(csv는 서식을 저장할 수 없으므로 도구 막대와 크기 조절을 비활성화하고 기본 모습으로만 표시)

### 반목표 (동작해도 이렇게 되면 실패)
- 서식을 바꿔 저장한 파일을 Excel이 "복구"하거나, 손대지 않은 칸의 서식이 바뀌는 것
- 서식을 고칠 때마다 `styles.xml`이 끝없이 커지는 것 (같은 서식은 재사용해야 한다)
- 2만 행 csv·xlsx에서 스크롤·입력이 1차보다 눈에 띄게 느려지는 것
- 1차에서 지키던 것(값 보존, 숫자형 문자열 보존, csv 방식 보존, 되돌리기, 필터 상태의 원래 행 번호 등)이 깨지는 것

## 3. 사용자가 정한 것
- 서식은 "다 적용"되어 Excel 모습 그대로 보여야 한다.
- 짧은 칸 입력과 여러 줄 칸 편집을 모두 지원한다.
- 서식 편집 기능을 넣는다. 범위는 위 목표 3번 목록("이 정도로 진행").
- 1차의 나머지 결정(새 창, 바로 덮어쓰기, 검색·필터 등)은 그대로.

## 4. Claude가 정한 것 (사용자 확인 대상)
- **진행 위치**: 1차 브랜치(`worktree-sheet-editor-v1`)는 아직 main에 합치지 않았으므로, 같은 브랜치 위에 이어서 만든다.
- **표 그리기**: Glide Data Grid는 세로 병합·칸별 테두리·행별 높이·여러 줄 칸을 함께 지원하지 못하므로, **표를 직접 그리는 캔버스 컴포넌트로 교체**한다. 보이는 영역만 그리는 가상 스크롤로 2만~5만 행에서도 지금 수준의 속도를 유지한다. 1차 표가 하던 일(선택, 키보드 이동, 편집, 붙여넣기·복사, 우클릭 메뉴, 행 머리글 열, 필터 행 매핑, 틀 고정)을 모두 새 컴포넌트가 맡는다.
- **서식 읽기**: `styles.xml`의 글꼴·채우기·테두리·셀 서식(cellXfs)·숫자 형식, `theme1.xml`의 테마 색(+ tint), 인덱스 색, 시트의 열 너비·행 높이·숨김·틀 고정·기본 행 높이를 읽어 모델에 담는다.
- **크기 환산**: 열 너비(문자 단위)와 행 높이(포인트)는 Excel과 같은 공식으로 픽셀로 바꾼다. 기준은 통합 문서 기본 글꼴의 숫자 폭이다.
- **글꼴 대체**: 맥에 없는 Windows 글꼴은 비슷한 글꼴로 바꿔 그린다(예: 맑은 고딕 → Apple SD Gothic Neo, Calibri·Arial → 시스템 산세리프). 파일 안의 글꼴 이름은 바꾸지 않는다.
- **숫자 형식**: Excel 형식 코드 해석은 검증된 라이브러리(SheetJS `ssf`, Apache-2.0)를 쓰는 것을 기본으로 한다. 한국어 요일·오전/오후 표기가 맞는지 테스트한다.
- **서식 편집 저장**:
  - 서식 변경도 1차와 같이 연산(Op)으로 기록하고, 저장할 때 원본 위에 다시 적용한다.
  - 새 서식은 `styles.xml`의 각 목록(fonts, fills, borders, numFmts, cellXfs) **끝에 추가**하고 `count`를 갱신한다. 기존 항목은 바꾸거나 지우지 않는다.
  - 이미 같은 조합이 있으면 그 번호를 재사용한다(반목표: styles.xml 무한 증가).
  - 칸에는 `s=` 번호만 바꾼다. 빈 칸에 서식을 주면 값 없는 `<c r s>`를 만든다.
  - 열 너비는 `<cols><col>`, 행 높이는 `<row ht customHeight="1">`, 병합은 `<mergeCells>`로 쓴다.
- **서식 적용 범위**: 선택한 칸에만 적용한다. 행·열 전체를 선택하면 사용 중인 범위 안의 칸에만 적용한다. 한 번에 바꾸는 칸이 20만 개를 넘으면 막고 안내한다.
- **병합하기**: 선택 범위에 값이 여러 개 있으면 Excel처럼 "왼쪽 위 값만 남는다"고 확인을 받은 뒤 병합한다.
- **새 파일**: 새로 만든 xlsx에서도 서식 편집이 되며, 저장할 때 서식이 함께 기록된다.
- **1차 제약 유지**: 그림·차트·메모·피벗이 있는 시트의 행·열 추가/삭제 차단 등은 그대로. 병합은 행·열 추가/삭제 때 함께 움직인다(1차에서 이미 파일 쪽은 처리됨, 화면 모델에도 반영 필요).

### 4-1. 검토 후 추가로 정한 것 (Claude 판단)
- **수정 표시**: 1차의 노란 배경은 실제 채우기 색과 헷갈리므로 없앤다. 대신 고친 칸의 **왼쪽 위에 작은 주황 삼각형**을 그린다. 값뿐 아니라 서식만 바꾼 칸에도 표시한다.
- **수정 여부**: 서식 변경(글꼴·채우기·테두리·병합·열 너비·행 높이 포함)도 "수정됨"(●)이며, 닫기·종료 시 저장 확인 대상이다. 값 연산과 같은 되돌리기 목록에 들어간다.
- **보존 원칙**: 1차와 같다. 손대지 않은 파트는 바이트 그대로, 고친 파트 안의 손대지 않은 부분은 의미가 같게 유지한다. `styles.xml`에 없던 목록(예: `numFmts`)을 새로 만들거나 시트에 `<cols>`·`<mergeCells>`를 새로 넣을 때는 스키마 순서에 맞는 자리에 넣는다. 범위로 묶인 `<col min max>`에서 한 열만 너비를 바꾸면 범위를 나눈다.
- **서식 상속**: 값이 없는 칸의 표시 서식은 Excel처럼 칸의 `s` → 행의 `s`(customFormat) → 열의 `style` → 기본 순으로 정한다. 그런 칸에 서식을 바꾸면 상속된 서식을 바탕으로 새 서식을 만든다.
- **단계별 진행**: ① 표시(새 캔버스 표 + 서식 읽기) → ② 편집(1차 기능 이식 + 여러 줄·병합 편집) → ③ 서식 편집과 저장. 각 단계가 끝날 때마다 앱이 동작하는 상태여야 한다.
- **한글 입력**: 편집기는 표 위에 띄우는 DOM 입력창으로 하고, 한글 조합(IME) 입력이 1차와 같이 자연스럽게 되어야 한다. 조합 중 Enter·방향키가 확정·이동으로 잘못 처리되지 않아야 한다. 이것은 필수 확인 항목이다.
- **csv 모습**: 1차 표와 비슷한 기본 모습(격자선, 시스템 글꼴, 같은 열 너비)으로 보인다. 열 너비·행 높이 조절은 그 창에서만 적용되고 저장되지 않는다. 서식 도구 막대는 비활성.
- **새 파일을 csv로 저장**: 서식이 하나라도 있으면 "csv에는 서식이 저장되지 않습니다"라고 확인을 받는다.
- **병합과 편집**:
  - 병합된 칸에 붙여넣으면 병합의 왼쪽 위 칸에 들어간다.
  - 붙여넣기 범위가 병합의 일부만 덮으면 Excel처럼 막고 "병합된 셀의 일부는 바꿀 수 없습니다"를 안내한다.
  - 서식을 줄 범위가 병합의 일부만 덮으면, 선택을 병합 전체로 넓혀 적용한다.
  - 행·열 삭제가 병합을 지나가면 병합을 줄이고, 한 칸만 남으면 없앤다(1차 파일 쪽 규칙과 동일하게 화면 모델에도 적용).
- **크기와 색의 기준**:
  - 열 너비 환산의 숫자 폭은 **원래 글꼴 기준값**을 쓴다(자주 쓰는 글꼴 표: 맑은 고딕·Calibri 11pt = 7px 등). 표에 없는 글꼴만 대체 글꼴로 잰다. 줄 바꿈 위치는 대체 글꼴 때문에 Excel과 조금 다를 수 있다.
  - 테마 색+tint, 인덱스 색, auto 색을 Excel 규칙대로 계산한다.
- **숫자 형식 성능**: 형식 결과를 (형식 코드, 값)으로 캐시해 2만 행에서도 스크롤이 매끄러워야 한다. 로캘은 한국어로 고정한다.
- **필터 상태의 서식 편집**: Excel처럼 **보이는 행에만** 적용한다.

## 5. 구현자에게 맡기는 것
- 캔버스 표의 내부 구조(그리기 계층, 히트 테스트, 스크롤 방식)
- 도구 막대의 구체적인 모양과 색 고르기 UI(기본 색 팔레트 + 최근 색 정도면 충분)
- 테두리 선 종류(점선·이중선 등)를 그리는 세부 방식
- 줄 바꿈 계산 방식(한글은 글자 단위로 줄 바꿈 가능해야 함)
- 테스트 전략. 다만 다음은 반드시 테스트해야 한다.
  - 서식을 바꿔 저장한 파일을 다시 읽으면 같은 서식이 나온다.
  - 서식을 바꿔도 손대지 않은 칸의 `s=`와 기존 styles 항목은 그대로다.
  - 같은 서식을 여러 번 적용해도 styles 항목이 늘지 않는다.
  - 열 너비·행 높이 환산이 Excel 값과 맞는다(대표 값 몇 개).
  - 숫자 형식 결과(특히 `m"월" d"일"`, 한국어 요일, 오전/오후, `#,##0`, 백분율).
  - 1차 테스트가 모두 그대로 통과한다.
